# SU-02 技術選型

- 日期：2026-10-18
- 狀態：已定案
- 任務代號：SU-02

## 結論

本專案採用純前端靜態網頁，不用框架、bundler 與後端。圖表庫選 **Apache ECharts 6.1.0**，由 cdnjs 載入並加上 SRI。

## 架構

- 純前端靜態網頁，部署在 GitHub Pages（`main` 分支根目錄）。
- `index.html`：單檔 Dashboard 主頁，CSS／JS 內嵌，不用 build 工具。
- `data/indicators.json`：指標目錄（分類、領先／同時／落後、資料來源、序列代碼、公布時間、判讀規則、講義頁碼）。
- `data/series/<ID>.json`：各序列的歷史資料，由 `tools/fetch-data.mjs` 抓取產生。
- 之後以 GitHub Actions 排程更新 `data/series/`。

### 選擇理由

ECharts 內建本專案需要的功能，不必另外裝 plugin：

- `dataZoom`：時間序列縮放。
- 雙 Y 軸：同圖比較不同單位的序列。
- 散佈圖：例如 Beveridge 曲線。
- `markArea`：NBER 衰退陰影。
- `markLine`：門檻線，例如 PMI 50、Sahm Rule 0.5。

### 比較過的其他方案

| 方案 | 結論 | 原因 |
|---|---|---|
| Chart.js | 不採用 | 時間軸、縮放、標註線都要另外裝 plugin。 |
| Plotly.js | 不採用 | 功能齊全，但檔案約 3.5 MB，載入負擔大。 |
| D3 | 不採用 | 太底層，開發量大。 |

### 指標目錄 `data/indicators.json`（DA-01 定案）

最上層：

- `version`：格式版號（整數，目前 1）。
- `updated`：目錄最後更新日期（`YYYY-MM-DD`）。
- `categories[]`：`{ id, name_zh, name_en }`，順序 C／I／G／NX／MC／IFU。
- `recession`：NBER 衰退期 `{ series: "USREC", source: "FRED", note }`，不算指標。
- `indicators[]`：各指標，欄位如下。

指標欄位：

- `id`：小寫 kebab-case 穩定代號（例如 `auto-sales`）。
- `category`：`C`／`I`／`G`／`NX`／`MC`／`IFU`。
- `name_zh`、`name_en`：中文名、英文原名。
- `timing`：`L`（領先）／`C`（同時）／`G`（落後）；講義未標時序者為 `null`。
- `timing_note`：講義較細的時序描述，沒有則 `null`。
- `frequency`：主序列頻率，`daily`／`weekly`／`monthly`／`quarterly`／`annual`。
- `release`：講義寫的公布規則（中文）。
- `series[]`：`{ id, source, role, substitute, note? }`；`role` 為 `main`（主序列）／`compare`（對照）／`component`（衍生計算用）；`substitute` 為是否替代序列。
  - `source`（DA-04）：`FRED`／`YAHOO`／`EIA`／`TRADINGVIEW`；DA-10 加 `CBOE`／`UST`。
  - 非 FRED 序列的 `id` 加來源前綴（`YF_`、`EIA_`、`TV_`），避免與 FRED 代碼撞名；抓取用的原始代碼另記：
    - `YAHOO`：`yahooSymbol`（如 `DX-Y.NYB` → `YF_DXY`、`GC=F` → `YF_GC`）。
    - `EIA`：`eiaSeries`（如 `WCESTUS1` → `EIA_WCESTUS1`）。
    - `TRADINGVIEW`：`tvSymbol`（如 `ECONOMICS:USBCOI` → `TV_USBCOI`）與 `tvInterval`（月 `1M`、日 `1D`）。
    - `CBOE`（DA-10）：`cboeSymbol`（如 `VIX` → `CBOE_VIX`），對應 Cboe 官方 `<cboeSymbol>_History.csv`。
    - `UST`（DA-10）：`fredBase`（FRED 原序列代碼，提供完整歷史）、`ustType`（財政部 CSV 的 `type`，如 `daily_treasury_yield_curve`、`daily_treasury_bill_rates`）、`ustColumn`（表頭欄名，如 `10 Yr`、`13 WEEKS BANK DISCOUNT`）。目前有 `UST_DGS10`（`DGS10`＋`10 Yr`）、`UST_DTB3`（`DTB3`＋`13 WEEKS BANK DISCOUNT`，即貼現率，不是 coupon equivalent）。
  - `lag`（DA-10，選填）：維持 FRED、但不是當天更新的日資料，畫面來源列加註「（延遲：…）」。目前：`DBAA`、`DAAA`、`BAMLC0A4CBBB`、`VIXCLS`「FRED 約落後 1 個營業日」；`DFF`、`SOFR`「官方次一營業日公布」；`DTWEXBGS`「Fed H.10 每週公布」。沒有此欄位＝不註記。
  - `note` 為畫面註明文字；替代序列以「替代：」開頭。
  - `axis`（UI-02，選填）：指標詳細圖的雙軸對照。`"right"` 表示畫在右 Y 軸；`"left"` 表示這條是雙軸對照的左軸序列（只在左軸序列不是 `main` 時才標，如債務槓桿的 `MABSHNO`）。沒有此欄位＝不參與雙軸對照。詳細圖的「主畫序列」為標 `axis: "left"` 的序列，沒有則為 `main`；3 月均／12 月均／YoY 都以主畫序列計算，右軸序列另畫一條原值（YoY 圖也加一條它的 YoY）。目前有：`CCSA`（右，左為 `ICSA`）[K 22]、`LNS12032194`（右，左為 `U6RATE`）[K 18]、`ACDGNO`（右，左為 `DGORDER`）[K 44]、`MABSHNO`（左）／`CMLBSHNO`（右）[K 77]。
- `derived`：衍生算法代號陣列（如 `yoy`、`qma`、`yma`、`mom_change`、`sahm`、`ratio_gdp`、`spread:A-B`、`beveridge`（失業率對職缺率的資料對））或 `null`；描述講義用到的算法，不一定都有對應的衍生檔。
- `derived_series`（DA-05，選填）：此指標已預先算好的衍生序列 id 陣列（如 `["DRV_CPI_YOY", "DRV_CPICORE_YOY"]`），對應 `data/derived/<id>.json`；沒有則不帶此欄位。
- `thresholds[]`：門檻線 `{ value, label, on?, series? }`，沒有則 `[]`。`on`（UI-02，選填）：`"yoy"` 表示畫在詳細圖下方的 YoY 圖（如「債務 YoY 3%」、「YoY 0 線」）；沒有此欄位＝畫在上方原值圖。YoY 圖本身一律另畫 0 線。`series`（選填）：門檻只適用於某個序列，詳細圖的主序列（`plan.left`）不是它時就不畫，避免把別的序列的門檻線畫在錯的數值上。
- `rule`：判讀規則（自行摘要）。
- `pages`：講義頁碼，如 `K 51–55`。
- `status`：`ok`／`substitute`（主序列為替代品）／`unavailable`（DA-04：沒有免費來源、不抓資料；`series` 為空陣列）／`pending`（尚待處理；DA-04 後已無此狀態）。
- `external`：講義使用的非 FRED 原始來源 `{ name, url?, note }`，沒有則 `null`；`unavailable` 的指標保留講義原來源名稱。`url`（DA-11，選填）：外部來源網址；舊資料沒有此欄位，讀取端要能缺省。
- `signal`（UI-03）：綜合訊號總覽的判斷規則（機器可讀）；不列入判斷的指標為 `null`（畫面算「不計」）。欄位：
  - `basis`：`raw`（最新值對門檻）／`yoy`（最新年增率 % 對門檻）／`trend`（近期均值對較長期均值）。
  - `series`：判斷用的序列代碼（可以不是 `main`，如耐久財用 `NEWORDER`）；`minus`（選填）：另一條序列代碼，表示用 `series − minus` 按日期對齊的利差判斷。
  - `expansionWhen`：`above`／`below`，比較值落在門檻（`trend` 為長期均值）哪一側算擴張；另一側算收縮。
  - `threshold`：門檻數值（`raw`／`yoy` 用；`yoy` 一律 `0`）。
  - `atThreshold`（選填）：剛好等於門檻時的狀態 `exp`／`neu`／`con`，預設 `neu`（Sahm Rule 設 `con`，即 ≥ 0.5 收縮）。
  - `neutralBand`（選填）：`[下限, 上限]`，落在區間內（含端點）為中性，區間外依 `expansionWhen` 判斷；有此欄就不用 `threshold`（如 VIX `[20, 30]`）。
  - `window`（`trend` 用）：`[短, 長]` 月數，目前固定 `[3, 12]`；視窗以最新一筆觀測的日期往回推算（取日期晚於「最新日期 − N 個月」的觀測），月／週／日資料一樣適用；資料不足長視窗則不計。
  - `note`：畫面提示文字；替代序列以「替代：」開頭。
- `light`（UI-11，選填）：卡片與總覽的 G／Y／R 燈號規則（G 綠＝沒問題、Y 黃＝警告再觀察、R 紅＝危險、「—」灰＝未判）。只給 `signal` 為 `null` 但講義有門檻的指標；不影響綜合訊號的擴張／收縮計數。格式 `{ series, rules, else, note }`：
  - `series`：判斷用的序列代碼，取最新值（原值，不轉換）；`DRV_` 開頭讀 `data/derived/<id>.json`，其餘讀 `data/series/<id>.json`。
  - `rules[]`：`{ when, value, light }`，依序比對、第一條成立者為準；`when` 為 `above`（>）／`atOrAbove`（≥）／`below`（<）／`atOrBelow`（≤）。
  - `else`：沒有任何規則成立時的燈號。
  - `note`：判斷依據（含講義頁碼），顯示在燈號的滑鼠提示。
  - 例：`{ "series": "DRV_DEFICIT_GDP", "rules": [{ "when": "below", "value": -3, "light": "R" }], "else": "G", "note": "…[K 67–68]" }`。
- 燈號判斷順序（UI-11，`index.html` 的 `evalLight`）：有 `light` 欄位以它為準；否則由 `signal` 的判斷結果推得：
  - `basis` 為 `raw`／`yoy`（門檻型）：擴張 → G、中性 → Y、收縮 → R（如 ISM < 50、Sahm ≥ 0.5、T10Y3M < 0 皆 R；VIX `neutralBand [20, 30]`：< 20 G、20–30 Y、> 30 R）。
  - `basis` 為 `trend`（近 3 月均對近 12 月均）：擴張 → G、中性或收縮 → Y（講義無危險門檻，不給 R）。
  - 兩者皆無、資料讀取失敗或不足 → 未判「—」。

### 序列 JSON `data/series/<ID>.json`（DA-02 定案）

欄位：

- `id`：序列代碼（FRED series id；非 FRED 序列為加前綴的代碼，與檔名相同）。
- `title`：指標名稱，「中文名 英文名」；只被對照／成分引用的序列後面加（`note`）；`USREC` 為「NBER 衰退期」。
- `source`：資料來源，`FRED`／`YAHOO`／`EIA`／`TRADINGVIEW`／`CBOE`／`UST`（同目錄的 `series[].source`）。
- `frequency`：頻率（`daily`／`weekly`／`monthly`／`quarterly`／`annual`），由觀測日期間距的中位數推斷。
- `units`：單位，目前固定 `null`（FRED CSV 不含單位；其他來源比照）。
- `substitute`：是否替代序列（目錄中任一引用為替代即為 `true`）；畫面需註明「替代」。
- `last_updated`：來源端資料最後更新日期（`YYYY-MM-DD`；沒有則 `null`）：
  - FRED：HTTP `last-modified`。
  - YAHOO：`meta.regularMarketTime`（交易所時區日期）。
  - EIA：頁面上的「Release Date」。
  - TRADINGVIEW：協定不提供，固定 `null`。
  - CBOE（DA-10）：HTTP `last-modified`（UTC 日期，Cboe 約美東收盤當晚更新，所以常是觀測日的次日）；沒有則用最後一筆觀測日。
  - UST（DA-10）：最後一筆有值的觀測日（財政部 CSV 沒有發布日期）。
- `fetched_at`：本機抓取日期（UTC，`YYYY-MM-DD`）。
- `observations`：`[["YYYY-MM-DD", number | null], ...]`，只保留 1970-01-01 起；缺值（FRED 的空值或 `.`）為 `null`。檔案內每筆觀測值一行，方便看 git diff。
  - YAHOO：日期以交易所時區（`meta.exchangeTimezoneName`）換算；收盤為 `null` 的列（非交易日）略過；盤中尚未收盤的當日那一根略過；數值為 float32，取 7 位有效數字。
  - EIA：週結束日（週五）；`-`／`NA`／`W` 等記為 `null`。
  - CBOE（DA-10）：取 `CLOSE` 欄；日期 `MM/DD/YYYY` 轉 `YYYY-MM-DD`；自 1990-01-02 起。
  - UST（DA-10）：先放 FRED `fredBase` 的完整歷史（含 `null`），再接上財政部 CSV 中晚於「FRED 最後一個有值日期」的日子；同一天兩邊都有值時以 FRED 為準。財政部只抓 FRED 最後有值日所在年到今年（1 月時自然含前一年）。依表頭名稱取欄位（欄位逐年增加）。
  - TRADINGVIEW：取收盤值。月線取年月、日固定 `01`。日線時間戳記若在 UTC 12:00 之後（交易時段從前一晚開始，如外匯／金屬現貨，時間戳記落在前一日 21:00–22:00 UTC），日期 +1 天；否則取 UTC 日期（如 `INDEX:BDI` 為當日 00:00 UTC，本來就正確）。

### 衍生序列 JSON `data/derived/<ID>.json`（DA-05 定案）

由 `tools/derive-data.mjs` 讀 `data/series/` 計算產生，網頁直接讀取，不在前端計算。執行順序：先 `node tools/fetch-data.mjs`，再 `node tools/derive-data.mjs`（兩者不串接；`derive-data.mjs` 不連網）。

欄位順序與序列 JSON 相同，再加三個欄位，`observations` 放最後：

`id`、`title`、`source`、`frequency`、`units`、`substitute`、`last_updated`、`fetched_at`、`inputs`、`formula`、`check`（選填）、`observations`。

- `id`：`DRV_` 開頭（如 `DRV_CPI_YOY`），與檔名相同。
- `title`：繁體中文名加英文名。
- `source`：固定 `DERIVED`。
- `frequency`：同序列 JSON，由觀測日期間距推斷。
- `units`：衍生序列已知單位，填文字（`%`、`百分點`、`千人`；Beveridge 為 `[失業率 %, 職缺率 %]`）。
- `substitute`：任一計算輸入為替代序列即為 `true`。
- `last_updated`：計算輸入的 `last_updated` 中最新的一個（都沒有則 `null`）。
- `fetched_at`：沿用此欄位名（相容序列 JSON），意義為衍生計算日期（UTC，`YYYY-MM-DD`）。
- `inputs`：計算用的輸入序列 id 陣列（只用於比對的序列不列入）。
- `formula`：算法說明（中文），含缺值處理與取幾位小數。
- `check`：與官方序列比對的統計 `{ against, n, max_abs_diff, mean_abs_diff, ... }`；沒有比對則不帶此欄位。
- `observations`：`[["YYYY-MM-DD", number], ...]`，不含 `null`（輸入缺值的點直接略過）；`DRV_BEVERIDGE` 每筆為 `["YYYY-MM-DD", 失業率, 職缺率]`。每筆一行。

目前的衍生序列：

| id | 輸入 | 算法 |
|---|---|---|
| `DRV_PAYEMS_MOM` | PAYEMS | 月增減（千人） |
| `DRV_PAYEMS_YOY` | PAYEMS | 年增率 % |
| `DRV_SAHM` | UNRATE（比對 SAHMREALTIME） | 3 個月平均 − 前 12 個月（t−12～t−1）3 個月平均最低值 |
| `DRV_CPI_YOY`、`DRV_CPICORE_YOY` | CPIAUCSL、CPILFESL | 年增率 % |
| `DRV_PCE_YOY`、`DRV_PCECORE_YOY` | PCEPI、PCEPILFE | 年增率 % |
| `DRV_PPI_YOY`、`DRV_PPIACO_YOY` | PPIFIS、PPIACO | 年增率 % |
| `DRV_BBB_AAA` | DBAA、DAAA | 日利差（百分點），同日兩邊都有值才算 |
| `DRV_DEFICIT_GDP` | MTSDS133FMS、GDP（比對 FYFSGDA188S） | 近 12 個月收支差額 ÷ 所屬季名目 GDP × 100，負值為赤字；該季 GDP 未公布時用最新一季 |
| `DRV_BEVERIDGE` | UNRATE、JTSJOR | 同月份的資料對，自 2000-12 起 |

年增率一律以日期對齊（本月 ÷ 12 個月前同月 − 1），不用陣列索引。輸入檔缺少或算出 0 筆的衍生序列不會建立或覆蓋檔案，其他照常寫入，結束碼為 1；寫檔方式同 `fetch-data.mjs`（寫前 `JSON.parse` 自我檢查、暫存檔改名）。

### FedWatch 機率 `data/fedwatch.json`（DA-11 定案）

下次 FOMC 會議的目標區間機率。CME FedWatch Tool 是參考來源，但其網站（含 QuikStrike）的 robots／使用條款禁止程式抓取，所以本站**不抓 CME**，改用 Yahoo Finance 的 30 天聯邦基金期貨（ZQ）各月合約，依 CME 公開的 FedWatch 方法論自算，畫面要註明「替代」。由 `tools/fetch-data.mjs` 產生（不帶參數時在所有序列之後產生；`node tools/fetch-data.mjs FEDWATCH` 只產生這個檔）。

計算方法（只算最近一場會議，單次會議、不做多場會議的機率樹）：

1. 會議日程：解析 federalreserve.gov FOMC 日程頁（`<h4>YYYY FOMC Meetings` 區塊的 `fomc-meeting__month`／`fomc-meeting__date`）。兩天會議取第二天為決策日；跨月（如 `Apr/May` `30-1`）取後一個月；日期欄不是純數字（notation vote、unscheduled 等）的略過。
2. 取決策日 ≥ 今天（美東日期）的第一場；決策日隔天生效。
3. 合約：`ZQ<月碼><YY>.CBT`（月碼 F G H J K M N Q U V X Z），Yahoo chart API `range=3mo&interval=1d`，不用連續月 `ZQ=F`。隱含利率 = 100 − 價格。
4. 會議月 N 天、會前 m 天（m = 決策日的日期）、會議月合約隱含平均利率 avg：
   - 下個月沒有會議 → 下月合約隱含利率為會後利率 post，會前 pre = (avg·N − post·(N−m)) / m（`method: "next_month"`）。
   - 否則前月沒有會議 → 前月合約為 pre，post = (avg·N − pre·m) / (N−m)（`method: "prev_month"`）。
   - 都不適用 → 失敗。
5. Δ = post − pre，除以 0.25 得步數 s；k = ⌊s⌋，目前區間平移 k 格的機率 1 − (s − k)，平移 k+1 格的機率 s − k。平移 < 0 歸「降息」、= 0「不變」、> 0「升息」。
6. 目前目標區間取 `data/series/DFEDTARL`、`DFEDTARU` 在各價格日或之前最近一筆，換成 bps；若最新一筆早於上一場已過會議的生效日，視為失敗（避免用到舊區間）。
7. 比較時點：`now` 用兩個合約最新的共同日線（盤中為最新價）；`1d`／`1w`／`1m` 以今天（美東）往前 1 天／7 天／1 個月（日期不存在取月底），取該日或之前最近、兩個合約都有收盤的交易日重算，同一場會議。

欄位：

- `source`：來源說明文字；`substitute`：固定 `true`；`reference_url`：CME FedWatch Tool 網址（只供畫面連結，不抓取）。
- `generated_at`：產生時間（ISO，UTC）；`as_of`：計算用的「今天」（美東日期）；`price_date`：`now` 用的價格日。
- `meeting`：`{ date, effective, contract, expires, price }`：決策日、生效日、會議月合約代碼（不含 `.CBT`）、到期日（合約月最後一個平日，未扣假日）、`now` 價格。
- `current_target`：`{ lower, upper }`（bps），`now` 價格日的目標區間。
- `probabilities`：`{ now, 1d, 1w, 1m }`，各為 `[{ range: "375-400", p: 0.845 }, ...]`（`p` 為 0～1，四位小數；機率為 0 的區間不列；依區間由低到高）。
- `summary`：`{ now, 1d, 1w, 1m }`，各為 `{ ease, no_change, hike }` 合計。
- `inputs`：`{ method, contracts, meeting_month_days, days_before_effective, horizons }`；`horizons.<時點>` 為 `{ price_date, prices: { 合約: 價格 }, target, avg, pre, post, delta }`（利率為百分比，六位小數）。

失敗處理：日程頁抓不到或解析不到會議、下個月份所在年度的日程還沒公布、Yahoo 合約抓不到或沒有收盤、某時點找不到共同交易日、目標區間檔缺少或不是 25bp 寬，都視為失敗：不建立、不覆蓋舊的 `data/fedwatch.json`，列在失敗清單，結束碼為 1（其他序列照常寫入）。寫檔同樣先 `JSON.parse` 自我檢查、暫存檔改名。

## 抓資料方式

- `tools/fetch-data.mjs` 使用 Node 24 內建 `fetch`，零套件。
- 依 `series[].source` 分派（DA-04），都不需 API key：
  - `FRED`：公開 CSV 端點（`fredgraph.csv?id=XXX&cosd=1970-01-01`）。
  - `YAHOO`：非官方 chart API（`query1.finance.yahoo.com/v8/finance/chart/<symbol>?period1=0&period2=<現在>&interval=1d`），送一般瀏覽器 User-Agent。不用 `range=max`（會降採樣成月／週線）。
  - `EIA`：官網歷史資料頁 HTML 表格（`eia.gov/dnav/pet/hist/LeafHandler.ashx?n=PET&s=<eiaSeries>&f=W`），每列一個「年-月」加最多 5 組「週結束日＋數值」。
  - `CBOE`（DA-10）：官方歷史 CSV（`cdn.cboe.com/api/global/us_indices/daily_prices/<cboeSymbol>_History.csv`，會 307 轉址到 `cdn-api.cboe.com`，`fetch` 預設跟隨），送瀏覽器 User-Agent。
  - `UST`（DA-10）：FRED CSV（`fredBase`）＋美國財政部每日利率 CSV（`home.treasury.gov/resource-center/data-chart-center/interest-rates/daily-treasury-rates.csv/<YYYY>/all?type=<ustType>&field_tdr_date_value=<YYYY>&page&_format=csv`），送瀏覽器 User-Agent。FRED 或財政部任一邊失敗，整個序列視為失敗、不覆寫舊檔。
  - `TRADINGVIEW`：非官方圖表 WebSocket（`wss://data.tradingview.com/socket.io/websocket`），用 Node 24 內建 `WebSocket`、未登入（`unauthorized_user_token`）。所有 TradingView 序列共用一條連線，整批逾時 30 秒；失敗只影響 TradingView 序列，其他來源照常寫入。非公開協定，可能改版或封鎖。
- 序列清單取自 `data/indicators.json` 所有 `series[]`，加上 `recession.series`（`USREC`），去重後共 68 個（FRED 59、YAHOO 2、EIA 1、TRADINGVIEW 3、CBOE 1、UST 2；DA-10 起 `DGS10`、`DTB3` 不在目錄內，由 `UST_DGS10`、`UST_DTB3` 抓取時一併讀 FRED，舊檔保留但不再自動更新）。
- `FEDWATCH`（DA-11）：不是序列，產生 `data/fedwatch.json`；讀 federalreserve.gov FOMC 日程頁＋Yahoo ZQ 各月合約（`query1.finance.yahoo.com/v8/finance/chart/ZQ<月碼><YY>.CBT?range=3mo&interval=1d`），送瀏覽器 User-Agent，重試同其他來源。格式與算法見上方「FedWatch 機率」。
- 用法：`node tools/fetch-data.mjs` 抓全部（最後產生 `data/fedwatch.json`）；`node tools/fetch-data.mjs DGS10 TV_BDI` 只抓指定序列（目錄外的代碼視為 FRED）；`node tools/fetch-data.mjs FEDWATCH` 只產生 FedWatch 機率。
- 每個序列最多重試 3 次（退避等待），序列之間間隔約 0.4 秒。
- CSV 表頭必須是 `observation_date,<ID>`、數值必須可解析、至少一筆觀測值，否則視為失敗；其他來源同樣要求數值可解析、至少一筆觀測值（Yahoo 另檢查回傳頻率為 `1d`）。
- 寫檔先寫暫存檔再改名（原子寫入）；失敗的序列不會建立或覆蓋檔案，其他成功的照常寫入。結束時列出成功／失敗清單，有失敗則結束碼為 1。

## 本機預覽

```bash
python3 -m http.server
```

必須透過 HTTP 開啟（例如 `http://localhost:8000`）。在 `file://` 下瀏覽器會擋 `fetch` 讀取 JSON。

## DA-03 資料排程的分支策略

- GitHub Actions（`.github/workflows/update-data.yml`）每日抓資料，bot 把 `data/` 的變動 commit 到 `main`。這是 CLAUDE.md「除 release 流程外不 push `main`」的例外。
- 為何例外：GitHub Pages 從 `main` 發佈，資料要直接上線才有「每日更新」的意義；若 commit 到 `dev`，要等人工 release 才會上線。
- 限制：bot 只 add `data/`，不碰程式與文件；沒有資料變動就不 commit。
- 合回 `dev`：同一個 job 在 push `main` 後，用 `--no-ff` 把 `main` 合進 `dev` 並 push。否則 `main` 上的資料 commit 與 `dev` 上的資料檔日後 release 時會在 `data/` 衝突。合併衝突時 abort、不 push `dev`，job 標失敗通知人工處理。
- 數據沒變不重寫檔（`fetched_at`／`generated_at` 不算變動），減少每日無意義的 commit 與合併。
- 實測結果：2026-10-18 在任務分支以暫時 push 觸發實測（run 39135563539）：GitHub Actions 雲端 IP 可連 TradingView WebSocket，69 個序列與 FEDWATCH 全部成功（FAIL 0），因此不需在 Actions 跳過 TradingView；暫時觸發已於合併前移除。
