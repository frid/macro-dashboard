## 結論

本專案採用純前端靜態網頁，不用框架、bundler 與後端。圖表庫選 **Apache ECharts 6.1.0**，由 cdnjs 載入並加上 SRI。

## 架構

- 純前端靜態網頁，部署在 GitHub Pages（`main` 分支根目錄）。
- `index.html`：單檔 Dashboard 主頁，CSS／JS 內嵌，不用 build 工具。
- `data/indicators.json`：指標目錄（分類、領先／同時／落後、資料來源、序列代碼、公布時間、判讀規則、講義頁碼）。
- `data/series/<ID>.json`：各序列的歷史資料，由 `tools/fetch-data.mjs` 抓取產生。
- 之後以 GitHub Actions 排程更新 `data/series/`。

## 圖表庫：Apache ECharts 6.1.0

- 版本：6.1.0（npm 發佈日 2026-05-19）。
- 來源：cdnjs。檔案 `echarts.min.js`，大小 1,121,883 bytes（約 1.07 MiB）。
- SRI（sha384）：`sha384-C2iskrW/uPW46KzOjrvJIQo4YkV8lkD+QS0CrDN18IIPIpT/g2USu8bTP3nvmIAD`
- 驗證方式：`curl` 下載取得 HTTP 200，再以 `openssl dgst -sha384 -binary | openssl base64 -A` 計算 hash。

引用範例：

```html
<script src="https://cdnjs.cloudflare.com/ajax/libs/echarts/6.1.0/echarts.min.js"
        integrity="sha384-C2iskrW/uPW46KzOjrvJIQo4YkV8lkD+QS0CrDN18IIPIpT/g2USu8bTP3nvmIAD"
        crossorigin="anonymous"></script>
```

若日後升版，必須重新計算 SRI 並同步更新 `index.html`。

### 選擇理由

ECharts 內建本專案需要的功能，不必另外裝 plugin：

- `dataZoom`：時間序列縮放。
- 雙 Y 軸：同圖比較不同單位的序列。
- 散佈圖：例如 Beveridge 曲線。
- `markArea`：NBER 衰退陰影。
- `markLine`：門檻線，例如 PMI 50、Sahm Rule 0.5。

### 比較過的其他方案

| 方案 | 結論 | 原因 |
|---|---|---|
| Chart.js | 不採用 | 時間軸、縮放、標註線都要另外裝 plugin。 |
| Plotly.js | 不採用 | 功能齊全，但檔案約 3.5 MB，載入負擔大。 |
| D3 | 不採用 | 太底層，開發量大。 |

## 資料格式（草案）

實際格式在 DA-01／DA-02 定案。序列 JSON 草案欄位如下：

- `id`：序列代碼（FRED series id）。
- `title`：指標名稱。
- `source`：資料來源。
- `frequency`：頻率。
- `units`：單位。
- `last_updated`：最後更新日期。
- `observations`：`[["YYYY-MM-DD", number | null], ...]`。

## 抓資料方式

- `tools/fetch-data.mjs` 使用 Node 24 內建 `fetch`，零套件。
- 來源：FRED 公開 CSV 端點（`fredgraph.csv?id=XXX`），不需 API key。
- 抓取失敗必須報錯並結束，不能寫入空檔覆蓋舊資料。

## 本機預覽

```bash
python3 -m http.server
```

必須透過 HTTP 開啟（例如 `http://localhost:8000`）。在 `file://` 下瀏覽器會擋 `fetch` 讀取 JSON。

## 不採用的東西

- 框架（React／Vue 等）。
- bundler（Vite／webpack 等）。
- 後端。
